## Problems found (need maintainer action)
1. Build failure on Xcode 26.6: `Pods/fmt` consteval errors ("call to consteval function ... is not a constant expression", format-inl.h). `pod install` did not help. Workaround used: edit gitignored `example/ios/Pods/fmt/include/fmt/base.h` so both `FMT_USE_CONSTEVAL 1` lines are `0`. Re-apply after any pod install that re-downloads fmt. This is an RN 0.78 / Xcode 26 toolchain issue, not the library.
2. Blank white screen with the repo's `example/metro.config.js` (New Arch). Console: `Invariant Violation: View config getter callback for component RNSVGPath must be a function (received undefined)`, thrown from `MaterialIcon -> Svg -> G -> Path`. Cause (verified in the bundle): two copies of `react-native` were bundled, one from `example/node_modules` and one from the pnpm store `node_modules/.pnpm/react-native@0.78.3_.../` (the one the root's react-native-svg resolves). The `blockList` regex only matches `root/node_modules/(react|react-native|react-native-svg)/`, not the realpath `root/node_modules/.pnpm/<pkg>@.../`, so the root copies are not blocked. Fix tested (config kept outside the repo): add `new RegExp(`${root}/node_modules/\\.pnpm/(react|react-native|react-native-svg)@.*`)` to `blockList`. With it, rendering works. The repo's `example/metro.config.js` was NOT modified (not my file); it needs this change. Untested: whether the same duplication happens for a user with a normal npm/yarn install.

## Fix — duplicate react-native in the example (2026-10-02)

- Cause: the library root is a pnpm workspace. Metro follows the root's `react-native` symlink to `<root>/node_modules/.pnpm/react-native@0.78.3_…/node_modules/react-native`, which the old `blockList` (direct paths only) did not match, so a second react-native was bundled and `RNSVG*` view configs failed to register (blank screen).
- Fix: `example/metro.config.js` also blocks `<root>/node_modules/.pnpm/(react|react-native|react-native-svg|@react-native+*)@…`.
- Measured with `npx react-native bundle --platform ios --dev false … --sourcemap-output`, counting distinct `react-native/Libraries/Renderer/implementations` roots in `sources`:

| | react-native copies | bundle size | exact icon set |
|---|---|---|---|
| before | 2 (`example/node_modules/react-native`, `node_modules/.pnpm/react-native@0.78.3_…`) | 1979 KB | OK |
| after | 1 (`example/node_modules/react-native`) | 1085 KB | OK |

- Simulator re-run with the committed config: not done (the render screenshots above were taken with an out-of-repo config carrying the same blockList rule).
- Scope: example-only. Consumers installing the tarball (docs/poc/2026-10-e2e-consumer.md) do not have a parent pnpm workspace and are unaffected.

## Environment note — Xcode 26.6 + RN 0.78

`Pods/fmt` fails to compile under Xcode 26.6 (consteval). Worked around locally by setting `FMT_USE_CONSTEVAL 0` in `example/ios/Pods/fmt/include/fmt/base.h` (Pods are gitignored, so this is not in the repo). This is an upstream RN 0.78 / Xcode issue, not a library issue.
